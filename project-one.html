Project One: Service Management System

Original Implementation with Comprehensive Unit Testing

Overview

Project One is a Java-based Service Management System demonstrating software testing and quality assurance principles. This is the original implementation showcasing fundamental object-oriented programming, data validation, and comprehensive unit testing.

Technology Stack: Java, JUnit

Key Concepts: Unit Testing, Data Validation, CRUD Operations, In-Memory Storage

GitHub: View Source Code

System Components

The system implements three independent service modules, each managing different types of data with strict validation rules:

1. ContactService

Manages contact information with the following fields:

  • Contact ID: Maximum 10 characters, not null, must be unique
  • First Name: Maximum 10 characters, not null
  • Last Name: Maximum 10 characters, not null
  • Phone Number: Exactly 10 digits, not null
  • Address: Maximum 30 characters, not null

Operations: Add contact, delete contact, update first name, update last name, update phone, update address

2. TaskService

Manages tasks with the following fields:

  • Task ID: Maximum 10 characters, not null, must be unique
  • Name: Maximum 20 characters, not null
  • Description: Maximum 50 characters, not null

Operations: Add task, delete task, update task name, update task description

3. AppointmentService

Manages appointments with the following fields:

  • Appointment ID: Maximum 10 characters, not null, must be unique
  • Appointment Date: Must be in the future, not null
  • Description: Maximum 50 characters, not null

Operations: Add appointment, delete appointment

Technical Implementation

Data Storage

All services use HashMap for in-memory storage, providing efficient O(1) lookup, insertion, and deletion operations. Each service maintains its own independent storage structure.

Validation Strategy

Comprehensive validation is implemented at the entity level to ensure data integrity:

  • All fields are validated upon object creation
  • Invalid data throws IllegalArgumentException with descriptive messages
  • Null checks prevent NullPointerException issues
  • String length constraints ensure data consistency
  • Date validation ensures appointments are scheduled for future dates

Code Example: Contact Entity

public Contact(String contactID, String firstName, String lastName, 
               String phone, String address) {
    if (contactID == null || contactID.length() > 10) {
        throw new IllegalArgumentException("Invalid contact ID");
    }
    if (firstName == null || firstName.length() > 10) {
        throw new IllegalArgumentException("Invalid first name");
    }
    if (phone == null || phone.length() != 10) {
        throw new IllegalArgumentException("Invalid phone number");
    }
    // ... validation continues
    this.contactID = contactID;
    this.firstName = firstName;
    // ... assignment continues
}

Testing Approach

Each service includes comprehensive JUnit tests covering:

Test Coverage

  • Happy Path Testing: Verifies correct behavior with valid inputs
  • Edge Cases: Tests boundary conditions (max length strings, minimum valid dates)
  • Negative Testing: Validates proper exception handling for invalid inputs
  • Duplicate Prevention: Ensures unique ID constraints are enforced
  • CRUD Operations: Verifies all create, read, update, delete functionality

Test Files

  • ContactTest.java: Tests Contact entity validation
  • ContactServiceTest.java: Tests ContactService operations
  • TaskTest.java: Tests Task entity validation
  • TaskServiceTest.java: Tests TaskService operations
  • AppointmentTest.java: Tests Appointment entity validation
  • AppointmentServiceTest.java: Tests AppointmentService operations

Key Features

  • Data Integrity: Strict validation rules prevent invalid data from entering the system
  • Unique Identifiers: Each entity has a unique ID that cannot be changed after creation
  • Immutable IDs: IDs are set during construction and have no setter methods
  • In-Memory Storage: HashMap provides fast lookups and modifications
  • Exception Handling: Clear error messages guide users when validation fails
  • Comprehensive Tests: JUnit tests ensure reliability and correctness

Lessons Learned

This project reinforced several important software engineering principles:

  • Validation is Critical: Early validation prevents cascading errors throughout the system
  • Test-First Mindset: Writing tests alongside code catches bugs early
  • Clear Error Messages: Descriptive exceptions help with debugging and user experience
  • Separation of Concerns: Keeping entities and services separate improves maintainability
  • Immutability Where Appropriate: Making IDs immutable prevents accidental modification
