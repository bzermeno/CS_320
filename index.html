📋 The Original: Project One - Service Management System

Java JUnit Testing Quality Assurance In-Memory Storage

Where It All Began: Project One was developed as a comprehensive demonstration of software testing and quality assurance principles. The focus was on creating well-tested, reliable code with proper validation and error handling. This project laid the foundation for understanding how to write maintainable, testable software.

The Three Core Services

ContactService

Manages contact information with comprehensive validation:

  • Contact ID (max 10 chars)
  • First & Last name (max 10 chars each)
  • Phone number (exactly 10 digits)
  • Address (max 30 chars)

Supports adding, deleting, and updating contacts with unique IDs.

TaskService

Manages tasks with field validation:

  • Task ID (max 10 chars)
  • Name (max 20 chars)
  • Description (max 50 chars)

Provides functionality to create, delete, and update tasks.

AppointmentService

Manages appointments with validation:

  • Appointment ID (max 10 chars)
  • Appointment date (must be in future)
  • Description (max 50 chars)

Enables scheduling and managing appointments.

    private Map<String, Contact> contacts = new HashMap<>();

    }
}

🚀 The Enhancement: RESTful API Layer

Spring Boot REST API JSON Modern Java HTTP Endpoints

The Evolution: The CS_320_Enhancement transforms the original service management system into a modern, web-accessible application. By adding a RESTful API layer using Spring Boot, the services can now be accessed by any HTTP client, opening possibilities for web applications, mobile apps, and system integrations. This enhancement demonstrates understanding of contemporary software architecture and API design principles.

What Changed and Why

🔵 Before (Original)

  • Java classes accessible only within application
  • Direct method calls
  • No external interface
  • Standalone desktop application
  • Limited to Java clients

🟣 After (Enhanced)

  • RESTful HTTP endpoints
  • JSON request/response format
  • Web-accessible API
  • Platform-independent access
  • Any HTTP client can connect

Enhanced Implementation Example

Here's the same ContactService, now enhanced with REST API endpoints:

@RestController
@RequestMapping("/api/contacts")
public class ContactController {
    
    @Autowired
    private ContactService contactService;

    @PostMapping
    public ResponseEntity<Contact> createContact(
            @RequestBody ContactDTO contactDTO) {
        try {
            Contact contact = contactService.addContact(contactDTO);
            return ResponseEntity.status(HttpStatus.CREATED).body(contact);
        } catch (IllegalArgumentException e) {
            return ResponseEntity.badRequest().build();
        }
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteContact(
            @PathVariable String id) {
        contactService.deleteContact(id);
        return ResponseEntity.noContent().build();
    }

    @PutMapping("/{id}")
    public ResponseEntity<Contact> updateContact(
            @PathVariable String id,
            @RequestBody ContactDTO contactDTO) {
        Contact updated = contactService.updateContact(id, contactDTO);
        return ResponseEntity.ok(updated);
    }
}

🛤️ The Enhancement Journey

From Desktop to Web: This section details the technical decisions and architectural changes made to transform a standalone Java application into a modern web service.

Technical Transformations

1. Architecture Evolution

Original Architecture

  • Monolithic Java application
  • Direct method invocation
  • HashMap in-memory storage
  • JUnit for testing

Enhanced Architecture

  • Layered REST architecture
  • HTTP-based communication
  • Service layer with DAO pattern
  • Spring Boot testing framework

2. Technology Stack Additions

  • Spring Boot: Enterprise-grade framework for building production-ready applications
  • Spring Web: For creating REST controllers and handling HTTP requests
  • Jackson: JSON serialization/deserialization library
  • Maven: Dependency management and build automation
  • Embedded Tomcat: Built-in web server for easy deployment

3. Design Patterns Implemented

Controller Pattern

Separates HTTP handling from business logic, making the code more maintainable and testable

Data Transfer Objects (DTOs)

Decouples API contracts from internal models, allowing independent evolution

Dependency Injection

Spring's IoC container manages object lifecycles and dependencies

RESTful Resource Naming

Clear, intuitive URLs following REST conventions

4. Code Quality Improvements

  • Error Handling: Centralized exception handling with proper HTTP status codes
  • Validation: Annotation-based validation with clear error messages
  • Logging: Comprehensive logging for debugging and monitoring
  • Documentation: Detailed API documentation with examples

Challenges Overcome

🎯 Key Challenges & Solutions

  • Date Handling: Migrated from java.util.Date to java.time.LocalDate for better thread safety
  • Validation: Implemented multi-layer validation (controller + service level)
  • Error Responses: Created consistent error response format across all endpoints
  • Testing: Adapted JUnit tests to work with Spring Boot's testing framework
  • Configuration: Externalized configuration for different environments

💭 Professional Reflection

Ensuring Functional and Secure Software

To ensure that my code, program, or software is both functional and secure, I follow a comprehensive testing and security strategy. Functionality begins with unit testing, where individual components are tested in isolation using JUnit. Integration testing follows, verifying that different parts of the program work together correctly, especially important in the REST API where controllers interact with services.

End-to-end testing simulates real-world usage to ensure the complete system performs as expected. Incorporating debugging tools and logging helps trace and fix issues effectively, while peer code reviews enhance quality by catching errors and suggesting improvements. Using version control systems like Git allows me to track changes and maintain a stable codebase.

Security Best Practices

  • Input Validation: All user inputs are validated to prevent injection attacks such as SQL injection or cross-site scripting (XSS)
  • Authentication & Authorization: The architecture supports adding secure protocols like OAuth2 or JWT
  • Data Encryption: Sensitive data can be encrypted both in transit (via TLS/SSL) and at rest
  • Security Testing: Both static and dynamic security testing, with consideration for penetration testing

Incorporating User Needs

Understanding and incorporating user needs into a program begins with effective requirement gathering. This involves user interviews, surveys, and behavioral observation. I've found success writing user stories in the format: "As a [type of user], I want to [perform some action] so that [benefit or goal]."

Once requirements are collected, I analyze and prioritize them, distinguishing between functional (what the system should do) and non-functional (how well it should do it) needs. Documenting user stories with flowcharts, mockups, or wireframes provides a visual understanding of user expectations. An iterative or agile approach allows for continuous user feedback and adjustments throughout development.

User-Centric Design Decisions

  • RESTful API: Chose standard REST conventions so developers familiar with HTTP can easily use the API
  • JSON Format: Selected JSON for its universal support and human readability
  • Clear Error Messages: Implemented descriptive error messages to help users understand and fix issues
  • Comprehensive Documentation: Created detailed API documentation with examples for easy onboarding

Approach to Software Design

Designing software starts with defining the problem clearly—understanding the goals, domain, and constraints. The next step is modeling the solution by breaking the system into logical components such as modules, classes, or services.

Visual tools like UML diagrams (use case, class, sequence, and activity diagrams) help in this phase. Selecting an appropriate architectural style—whether monolithic, microservices, or MVC—is essential for ensuring scalability and maintainability. Clearly defined interfaces and APIs enable smooth communication between system components, especially in distributed or web-based applications.

Design Principles Applied

  • SOLID Principles: Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion
  • DRY (Don't Repeat Yourself): Eliminated code duplication through proper abstraction
  • KISS (Keep It Simple, Stupid): Prioritized simplicity and clarity in implementation
  • YAGNI (You Aren't Gonna Need It): Avoided over-engineering by implementing only what's needed
  • Separation of Concerns: Clear boundaries between layers (Controller, Service, DAO)
